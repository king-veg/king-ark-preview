# EYE v2 — JOKER WEB DESIGN 品質監査基準

EYEはKINGへ提出する直前の最終品質監査。制作担当とは分離して判定し、推測でPASSにしない。

## 絶対ルール
1. 全項目を実物で確認する。コード上の存在だけではPASS不可。
2. 1項目でもNGまたは未確認ならKING提出禁止。
3. NGはJOKERへ差し戻し、修正後に全項目を再監査する。
4. 「たぶん」「環境次第」「見た感じ」はPASS理由にしない。
5. KINGの指定条件を監査票の最上位条件として扱う。

## A. 画像・素材監査（v2強化）
- [ ] 全画像がエラーなく取得できる
- [ ] 画像ファイルが破損していない
- [ ] 灰色/空白/欠損表示がない
- [ ] PC/スマホ双方で意図しない見切れがない
- [ ] object-fit / object-position が人物・商品の重要部分を切っていない
- [ ] 引き伸ばし・縦横比崩れがない
- [ ] 解像度不足・強いボケ・圧縮劣化がない
- [ ] Retina相当でも商品品質を保つ
- [ ] 遅延読み込み画像もスクロール後に正常表示
- [ ] 外部画像URLに期限切れ・認証依存がない
- [ ] 指定人物/テイスト/ブランド条件と素材が一致
- [ ] altが内容と矛盾していない

## B. レスポンシブ・実表示監査
- [ ] 390px級スマホで横スクロールなし
- [ ] iPhone/Safari想定で全sectionが破綻しない
- [ ] PCでも余白・文字組・画像比率が破綻しない
- [ ] sticky/fixed要素が本文やCTAを不当に隠さない
- [ ] safe-area考慮
- [ ] フォント失敗時も読める
- [ ] JS待ちで本文が永久に透明にならない

## C. 操作・導線監査
- [ ] ナビが正しいsectionへ移動
- [ ] モバイルメニュー開閉・aria-expanded・閉じ動作正常
- [ ] CTA/予約/電話/戻るリンク正常
- [ ] ダミーリンク(#)を完成扱いしない
- [ ] スクロール演出正常
- [ ] reduced-motionでも閲覧可能

## D. デザイン・ブランド監査
- [ ] KING承認済み方向性と一致
- [ ] 色・余白・文字・写真トーン統一
- [ ] 安っぽい素材・不自然なトリミング・テンプレ感なし
- [ ] スマホでも高級感を維持
- [ ] 誤字・不自然な改行・文字切れなし
- [ ] 想定価格帯の商品として説明可能な完成度

## E. 技術・公開監査
- [ ] HTML/CSS/JS参照切れなし
- [ ] console errorなし
- [ ] 公開URLで対象版が反映済み
- [ ] キャッシュ更新後も正常
- [ ] 404/壊れたasset/期限付きassetなし
- [ ] title/description/viewport正常

## 判定
- PASS: A〜Eの全必須項目を実確認しNGなし
- REJECT: 1件以上NG
- HOLD: 実機/公開URLなど未確認項目が1件以上

HOLDをPASSとして扱わない。

## EYE → JOKER 差し戻し
判定 / 箇所 / 症状 / 再現条件 / 修正要求 / 再監査対象 を必ず記録する。

## KING提出条件
「EYE v2: PASS」と監査対象の公開URL/版を明記する。未確認項目がある場合は提出禁止。

## 強制執行ゲート（KING提出前・例外なし）

このセクションは最優先ルールとして扱う。

1. KINGへ制作物・公開URL・完成スクリーンショットを提出する前に、必ずEYE v2監査を実行する。
2. 監査を省略・短縮・推定で代替してはならない。「コード上は問題ない」「表示できそう」は確認扱いにしない。
3. MASTER DESIGNが承認済みの場合、実レンダリング結果とMASTERを比較し、Hero構図、画像、セクション順、配置、比率、余白、文字の強弱、色、全体密度、ブランド表現の一致を確認する。
4. 指定ASSETがある場合、実サイトでその指定素材が使用されていることを確認する。代替素材への無断差し替えは禁止する。
5. 商品プラン・価格・確定仕様を監査前に照合する。確定値と異なる場合はREJECTとする。
6. PC・Mobile・画像品質・主要導線・レスポンシブ・MASTER一致・ASSET一致・価格帯品質の必須項目がすべて確認済みでなければPASSにしない。
7. NGが1件でもあればJOKERへ自動差し戻し。修正後は該当箇所だけでなくEYE v2を再実行する。
8. 確認不能項目がある場合はHOLD。HOLD状態の制作物をKINGへ「完成版」として提出してはならない。
9. KINGへの完成提出には必ず「EYE v2: PASS」を付与する。途中確認の提出にも「EYE v2: DIRECTION PASS」を必須とする。いずれのPASS記録も存在しない制作物は提出禁止。
10. KINGが「途中を見せて」「見せて」「確認したい」等を依頼した場合もEYE v2監査を必ず実行する。途中版であっても未監査の制作物をKINGへ提示してはならない。途中段階では、少なくともMASTER DESIGNとの方向性一致、確定プラン・価格、指定ASSET、主要レイアウト、表示崩れを監査し、NGまたは未確認があれば提示前にJOKERへ差し戻す。

### JOKER強制ルール
「できたから見せる」ではなく「EYE v2を通過し、出してよい品質だから見せる」。
KINGの目視確認をQA工程の代替にしない。KINGは不具合発見係ではなく、最終判断者とする。


## 常時監査ループ（制作中・必須）
EYE v2は「完成後の最終検査」ではなく、制作工程そのものに組み込む。

基本単位：
依頼 → 1つ作る/1つ変更する → EYE監査 → NG修正 → EYE再監査 → PASS → 次の作業

強制ルール：
- 複数の変更をまとめて最後に一括監査してはならない。
- セクション追加、画像差替え、レイアウト変更、レスポンシブ修正、導線追加など、意味のある1変更ごとにEYEを通す。
- EYEでNGを検出した場合、その場で修正し、PASSするまで次の制作工程へ進まない。
- 途中で方向性がMASTER DESIGNからズレた場合は即REJECTし、積み上げを続けない。
- KINGへの提出前監査は、この常時監査ループを通過した制作物に対する最終確認として行う。
- KINGはバグ発見係ではなく、方向性・好み・微調整の最終判断者とする。

目的：
バグや方向ズレを最後にまとめて発見するのではなく、発生した直後に潰し、次工程へ持ち越さない。
